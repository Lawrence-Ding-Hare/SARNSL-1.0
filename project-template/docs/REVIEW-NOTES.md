# 审阅结论与设计决策

## 设计目标

- **直接衍生版免费分发。** 复制、换名、重新打包，或只加少量功能不能逃避免费要求。
- **独立付费产品可集成。** 只有在定价能由实质独立功能或服务支撑，且受约束功能无需单独付费或升级即可取得时才适用。
- **防止变相收费。** 付费支持、托管、账号或安装服务必须真正可选。不能作为获取免费软件或直接衍生版的门槛。
- **源码义务明确。** 分发修改版或未修改的受约束二进制时，为接收者提供准确版本的完整对应源码。链接或书面承诺需保持至少三年。
- **外部服务公开源码。** 修改版网络服务的外部用户可取得准确部署版本对应源码。仅在同一法律主体内部使用的服务豁免。
- **归属可追溯。** 分发和对外提供服务时注明上游项目名称与官方 URL，保留原作者署名。
- **明确授权范围。** 第三方内容和旧版本适用其原许可。新许可不追溯撤销旧许可。

## 许可证类型

SARNSL 限制直接衍生版有偿分发，因此它属于自定义的源码可见许可证，不是 OSI 定义下的开源许可证。GitHub 可能把它显示为自定义许可。

根目录的 CC0 仅开放本协议仓库中作者有权放弃或授权的协议、译文、模板及说明文本。它不代表下游软件自动采用 CC0。下游软件须自行采用 SARNSL 并逐项标注版权与适用范围。

## 需要每个采用项目填写的内容

- 版权人和其有权授权的文件。
- 项目名称和官方仓库链接。
- 第三方材料、上游作品和合作者贡献的例外。
- 联系渠道及首次采用的版本标签或提交。

本稿不代表对任何具体项目中所有文件权属的自动核验。修改已有仓库前，须逐项确认有权重新授权。
